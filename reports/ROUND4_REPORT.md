## 1. R4-1 冻结输入与状态的对应关系

### 1.1 提示截断核验（实测，无需 GPU）

`ModelHelper.get_activations()` 用 `max_length=512`，`generate()` 用 `max_length=1024`。逐条重算：

| 项 | 结果 |
|---|---|
| 提示真实 token 长度 | **182 – 232**（激活上限 512） |
| 触发 512 截断的输入 | **0** |
| 两种上限下 input_ids 是否一致 | **160/160 一致** |
| 激活张量行数 vs 输入数 | 160 vs 160 |
| **结论** | **现有激活可直接复用，无需重采集** |

token 位置：`padding_side="left"`，取 `hidden[:, -1, :]`，即**每行最后一个真实 token**。

### 1.2 状态语义（代码检查，已写入产物）

激活在**挂 steering hook 之前**只采集一次，因此它是**无干预生成前状态**，**只与 No Steering 回答配对**，**不得**被描述为三种干预后的状态。`activation_manifest.json` 的 `alignment.state_semantics` 字段已固化此约定。

### 1.3 生成终止原因（实测，本轮新采集）

原脚本只记录非空回答，无法排除截断。已给 `ModelHelper` 增加 `generate_with_meta()`，逐样本记录 `n_new_tokens / hit_max_new_tokens / stopped_on_eos / finish_reason`。

| 运行 | 撞 token 上限 | 正常 EOS 结束 |
|---|---|---|
| cap**256**（原主运行） | **72/160 = 45.0%** | 88/160 |
| cap**512**（敏感性运行） | 32/160 = 20.0% | 128/160 |

三个条件（No Steering / Standard / CI）在各自运行内撞限数量完全相同（72/72/72 与 32/24/32）。

**截断估算的陷阱（实测）**：对解码后的回答重新分词并计数，得到"≥256 token 者 22 条"；而真实终止原因是 **72 条**。**长度估算把截断低估了 3 倍以上**，这与复核 §4.4 的判断一致：不能靠非空回答或长度推算排除截断。

### 1.4 确定性核验（实测）

同一配置重跑一次，**480/480 条回答逐字一致**（贪心解码，`temperature=0`）。因此升级脚本加入终止元数据后，行为结论未发生任何变化。

**产物**：`activation_alignment/activation_manifest.json`、`activation_alignment/activation_rows.jsonl`（逐行 `row_index → input_id`、token 数、是否截断、有效 input_ids 哈希）。

## 3. R4-3 生成状态规范探针（真正的分组 OOF 探针）

脚本 `src/probe_generation_state.py`。Y = 1 当且仅当**授权者就是被请求条目的所有人**。

### 3.1 纪律（代码检查）

- 只用**无干预的 160 条状态**；**未**加入规范问答、标准答案或模型回答作为特征。
- 外层按 **base scenario 分组**：一个场景的 8 个变体**永不分开**。
- 标准化、PCA、C 与 PCA 维度**全部只在训练部分拟合**；选层同样在**内层分组 CV**（仅训练组）中进行，**从未**在 outer test 或全 160 上选最好结果。
- 保存全部 outer 折与**所有** out-of-fold 预测。

### 3.2 主结果（实测）

| 臂 | AUROC | balanced accuracy |
|---|---|---|
| **选层臂（5 折分组，层由内层 CV 选）** | **0.9800** | **0.9063** |
| 留一场景（20 折）稳健性 | 0.8905 | 0.8125 |
| 第 0 层对照 | 0.4720 | 0.4875 |
| 输入文本 TF-IDF 对照 | 0.5017 | 0.5313 |
| 姓名/角色 one-hot 对照 | **0.5000** | 0.5000 |

**置换零假设**（30 次打乱，复用同一预处理缓存）：均值 **0.6066**、p95 **0.6661**、最大 0.6859；观测 0.9800 ⇒ 经验 p < 1/30。

> 注意零假设均值 **0.607 高于 0.5**：因为该流程含**选层**步骤，打乱标签后仍会被选层抬高。这正是必须做置换对照的原因——对照不是 0.5，而是 0.607。

### 3.3 逐层曲线（实测）

| 层 | AUROC | | 层 | AUROC |
|---|---|---|---|---|
| 0 | 0.472 | | 12 | 0.971 |
| 3 | 0.779 | | **14–20** | **1.000** |
| 4 | 0.841 | | 21–23 | 0.999 |
| 6 | 0.938 | | 24 | 0.998 |
| 7 | 0.896 | | 25 | 0.997 |
| 10 | 0.889 | | 26–27 | 0.998–0.999 |

**逐层曲线仅为诊断**：每层各自用了自己的内层 CV 超参数，**不是**与选层臂的公平排名。

**选层来源（实测）**：内层 CV 在 5 折上分别选了层 **4 / 6 / 12 / 13 / 13**，留一场景下选了层 **2 / 3 / 4**。**选层结果不稳定**，因此可靠表述是"**约第 3 层起可解码，第 14 层附近饱和**"，**不是**"某个特定层是规范层"。

### 3.4 解释限制（写入产物 `interpretation_guard` 字段）

一个场景的 allow/disallow 变体**只差授权者姓名**，所以 Y 本质是**关系匹配**（"被点名的授权者是不是被请求条目的所有人？"）。因此：

- 可解码**说明该关系存在于无干预状态中**；
- **不**说明存在隐私专用机制（TF-IDF 与姓名 one-hot 均失败只说明该关系不在表面词袋里，**不**足以推出机制专用）；
- **不**说明模型在生成时因果地使用了该关系（本轮未做因果干预）；
- 20 个场景仍是**开发数据**，交叉验证**不会**把它变成未见正式测试集。

## 4. R4-4 规范预测 × 行为联表与分支判断

### 4.1 联表（实测，n=147）

| 探针预测 | 披露 | 未披露 |
|---|---|---|
| **正确** | 94 | 38 |
| **错误** | 14 | 1 |

### 4.2 关键交叉（实测）

**未授权组**：

| 量 | 值 |
|---|---|
| 披露 vs 未披露的探针均分 | 0.1298 vs 0.0617（均为 P(allow)） |
| **由探针分数预测是否披露的 AUROC** | **0.526**（≈ 机会） |
| 规范说对（54 例）中探针也预测正确 | **52 例** |
| 规范说对**且仍披露**（15 例）中探针预测正确 | **全部落在这 52 例内** |

**已授权组**：78/78 全部披露，**无对比可言**（不能计算该组"披露的 AUROC"）。

### 4.3 分支判断（实测 + 推断）

复核给出的分支规则：*若可靠规范预测与泄露并存 → 优先比较"错误授权归属"与"正确声明但拒绝中泄露"。*

- 可靠规范预测？**是**（OOF 0.980，远超置换 p95 0.666）。
- 泄露并存？**是**（未授权 43.5%）。
- ⇒ **落入分支一**。

两个待比较的错误类型在本轮已可定量：

| 错误类型 | 数量（disallow，n=69） |
|---|---|
| **A：授权归属错误 / 未表现判断后直接披露**（规范声明错误或缺失） | 15 |
| **B：正确声明规范但仍披露** | **15**（9 例声明在披露前，6 例在披露后） |
| 其中探针在状态层面预测正确的 | 52/54 ⇒ **B 类主要不是"状态里没有规范"** |
| 探针置信度与是否披露的关系 | AUROC 0.526 ⇒ **几乎没有关系** |

**结论（推断，需人工标签确认后才能升级为结论）**：在这批数据上，"状态中可解码的正确规范"与"实际是否披露"**几乎不相关**。若人工标签支持这一点，下一步就值得采集**首次披露之前**的解码阶段状态（而不是只看提示末尾的单一前向状态），以判断规范是否在生成过程中被逐步覆盖。

**同时必须声明**：本轮**没有**做任何因果干预，因此**不能**说"模型知道却不执行"。能说的只是：在提示末尾的无干预状态中，规范标签可被线性解码，而该解码的强弱不预测行为。

### 6.6 需要用户决定的口径

**以哪一次运行作为行为分析的主运行？** cap256（原主运行，45% 被截断）或 cap512（20% 被截断）。配对差异仅 1 例（p=1.0），但**若要让主分析尽量少受截断影响，应改用 cap512 并明确记录这是事后选择**。
